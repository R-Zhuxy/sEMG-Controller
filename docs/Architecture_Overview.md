# sEMG 体感交互控制系统 - 架构与核心实现全解
*(Architecture Overview & Implementation Details)*

本文档针对单通道 sEMG 体感交互控制系统的底层架构、软硬件通信协议以及信号处理算法进行了深入剖析。可用于项目梳理、技术回顾以及学术答辩。

---

## 1. 系统总体架构与数据流 (System Architecture & Data Flow)

系统整体遵循**管道-过滤器 (Pipeline)** 架构，主干数据流将传感器获取的物理信号一步步转化为最终的计算机输入指令。

**核心流水线 (`main.py`):**
`Arduino (ADC)` ➔ `SerialReader` (串口通信) ➔ `RingBuffer` (缓存机制) ➔ `SignalFilter` (陷波+带通) ➔ `EnvelopeExtractor` (RMS包络与平滑) ➔ `Calibrator` (阈值自适应) ➔ `SchmittTrigger` (状态决策) ➔ `KeyMapper` (动作注入)。

### 1.1 `main.py` 中的主数据流解析
主程序采用了**主次线程分离、流式异步处理**的模式：
1. **数据采集 (异步生产者)**：`SerialReader` 在后台作为独立守护线程运行，将串口传来的肌电电平值解析后批量压入 `RingBuffer`。
2. **信号处理 (同步消费者)**：主线程通过 `while not shutdown_flag:` 循环，以大约 200Hz 的频率 (受 `time.sleep(0.005)` 控制) 处理数据。
3. **严格连续的流式处理 (Streaming Processing)**：每次循环主线程调用 `buffer.read_new()`，**只获取未被处理的全新增量数据**。由于滤波器和包络提取器都在内部维护了跨数据块的状态 (Stateful)，这使得按小数据块连续处理与直接处理整个长序列获得完全一致的相位与幅值结果。

## 2. 软硬件通信与抗噪协议 (Hardware-Software Communication)

物理世界充满了不确定性。本系统的软硬件通信设计在严格遵循“非阻塞”原则的基础上，构建了健壮的连接机制。

### 2.1 下位机：基于 `micros()` 的严格定时 (`semg_reader.ino`)
- **绝对禁止 `delay()`**：固件层面杜绝了 `delay()` 函数，完全依赖 `micros()` 判定系统时间是否达到了 2000μs (500Hz)。
- **防时间漂移**：采用 `lastSampleTime += SAMPLE_INTERVAL_US;` 累加时间，而不是赋值为当前的 `micros()`，从而消灭了由于 `analogRead` 自身执行耗时引起的长程时间漂移。
- **预热机制**：刚上电启动时，连续读取丢弃了 16 次 ADC 数据，确保内部采样保持电容充分充电。

### 2.2 串口握手协议与容错 (`serial_reader.py`)
- **"READY" 哨兵帧**：由于 Arduino 重启时会发送杂乱电平，下位机完成预热后主动发出 `READY\n` 哨兵帧。上位机 `SerialReader` 连接时监听此哨兵帧，以此代替传统且低效的“盲等2秒”。
- **误码计数与防洪泛 (Anti-Flooding)**：在解析 `readline()` 遇到乱码或无法转换的文本时，不抛出异常导致线程崩溃，而是记录误码。为防止日志瞬间被撑爆，仅在错误次数 <=10 或整数百次时打印日志。
- **降低 96% 的锁争用 (`_BATCH_SIZE`)**：串口守护线程如果不加约束，每 2 毫秒就会向 `RingBuffer` 写入 1 个样本并抢占 1 次锁。设计中引入了容量为 25 (`_BATCH_SIZE`) 的局部数组，积攒 25 个样本才一次性 `extend` 入队。加锁频率从 500次/秒骤降至 20次/秒。

## 3. 高性能内存与状态管理 (High-Performance Memory Management)

为了能够在 Python 下跑满 500Hz 并且满足信号处理需要，对内存流转进行了专门设计。

### 3.1 `ring_buffer.py` 的读写分离与无锁化思想
基于固定的 numpy 数组预分配 (`capacity=2048`) 避免了动态扩容带来的 GC 开销。
- **分离指针设计 (Separated Pointers)**：
  - 维护三个核心指针：`_write_index` (写循环指针)、`_total_written` (总写入量)、`_read_index` (流式处理专用读指针)。
  - `read_new()` 方法：消费者通过此方法读取从 `_read_index` 到 `_total_written` 之间的所有新样本，并在读后自动推进 `_read_index`。
- **数据连续性保证**：由于每次只消费增量数据，这极好地契合了流式信号处理的需求，避免了每次滑动窗口处理必须产生重叠所带来的冗余计算和时序倒流风险。

## 4. 信号处理算法核心设计 (Signal Processing Algorithms)

这是系统抗干扰的最核心部分，面对 50Hz 工频干扰和基线漂移，作出了极具针对性的设计。

### 4.1 流式数字滤波器 (`filters.py`)
所有的滤波均采用 IIR 滤波器（运算量小）。
- **宽容度的多谐波陷波 (Notch Filter)**：
  为了滤除 50Hz 工频，采用了 `scipy.signal.iirnotch`。值得注意的是，工业电网频率并非绝对精确的 50.00Hz，而是存在微小频偏。系统特意将 Q 值从极高值降到 15 (带宽约 3.3Hz)，增加了鲁棒性。
- **SOS 级联带通 (Bandpass Filter)**：
  为了保留 20-200Hz 的有效肌电，去除了运动伪影 (<20Hz)。算法采用二阶截面 (`sosfilt`) 格式而非普通的 `(b, a)` 传递函数，以防止高阶 IIR 滤波器带来浮点截断误差和系统发散。
- **流式状态保持 (`zi`)**：
  跨越连续的数据块维护内部记忆缓冲 `zi`（包括陷波器的 `zi` 和 SOS 的 `zi`），确保流式切片处理不会产生任何边界畸变。

### 4.2 流式包络线提取 (`envelope.py`)
传统算法通过 `np.mean(x**2)` 计算 RMS，在每次取滑动窗口时极度耗费性能且容易出现首尾衔接问题。本系统自创了真正的 **O(1) 状态机包络累积法**：
1. **全波整流**：逐样本计算平方。
2. **滑动 RMS (O(1))**：维护一个长度为 `rms_window` 的环形数组记录过去的平方值，仅通过加上新样本平方、减去旧样本平方来更新 `sum_sq`，再开根号。单样本时间复杂度严格控制为 O(1)。
3. **滑动平均**：同理使用 O(1) 滑窗求和计算平滑。
这种算法允许一次性传入极短（甚至 1 个样本）的数据块而毫无边界效应。

## 5. 决策与控制层 (Decision & Control)

### 5.1 自适应校准与施密特触发器 (`calibration.py` & `SchmittTrigger`)
- 肌肉放松时的本底噪声因人而异、因贴片而异。系统启动时强制经历自适应校准 (`run_calibration`)。
- 采用 **施密特触发器 (Schmitt Trigger)** 防抖：
  - 高阈值 (High Threshold)：用于判定肌肉收缩。设定为 `基线均值 + 3.0 倍标准差`。
  - 低阈值 (Low Threshold)：用于判定肌肉放松。设定为 `基线均值 + 1.5 倍标准差`。
  双阈值设计形成“滞回区间”，从根本上消灭了发力维持期间，由于包络线自身小幅抖动引起的键盘疯狂连击 (Debounce)。

---

## 总结
该架构巧妙地将非阻塞硬件轮询、基于流式消费分离指针的内存缓存机制、以及极低开销的 O(1) 状态机信号处理结合在了一起。实现了稳定 500Hz 采样率下，既具备医学级抗噪能力，又满足了体感游戏要求极低的“端到端延迟”标准。
